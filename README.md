# موقع مدرسة النهروان

## تسجيل الدخول والصلاحيات

الموقع للطلاب والزوار للقراءة فقط ولا يحتاجون إلى حساب. النشر متاح لحساب الإدارة الوحيد، وتُفرض الصلاحية على الخادم أيضًا؛ إخفاء أزرار النشر في الصفحة ليس وسيلة الحماية.

قبل تشغيل الخادم، أضف هذه المتغيرات إلى إعدادات البيئة السرية في الاستضافة:

- `ADMIN_USERNAME`: اسم حساب الإدارة.
- `ADMIN_PASSWORD`: كلمة مرور قوية لا تقل عن 12 حرفًا.
- `SESSION_SECRET`: سر عشوائي لا يقل عن 32 حرفًا، ويجب أن يبقى خاصًا بالخادم.

يمكن توليد سر جلسات عشوائي باستخدام Node.js:

```powershell
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

لا تضع كلمات المرور أو أسرار الجلسات في ملفات المشروع أو المستودع. يستخدم الموقع جلسة موقعة في ملف تعريف ارتباط `HttpOnly` و`SameSite=Strict`، وتنتهي الجلسة بعد 8 ساعات أو عند إعادة تشغيل الخادم. فعّل HTTPS في الإنتاج؛ يضيف الخادم خاصية `Secure` إلى ملف تعريف الارتباط عند تشغيل `NODE_ENV=production`. تُحدّ محاولات الدخول الفاشلة إلى خمس محاولات لكل عنوان خلال 15 دقيقة.

لا يوجد تسجيل حساب للزوار؛ الإضافة متاحة لحساب إدارة واحد فقط. لفتح صفحة الإدارة، اضغط على كلمة «القائمة» سبع مرات متتالية في الصفحة الرئيسية ثم سجّل الدخول ببيانات الإدارة المضبوطة في متغيرات البيئة. بعد الدخول يمكنك العودة إلى الموقع، وسيظهر زر إضافة الإعلان وأدوات الإدارة.

## تشغيل الموقع

يتطلب الموقع استضافة تدعم Node.js. في PowerShell، شغّل الموقع محليًا بعد ضبط متغيرات البيئة:

```powershell
$env:ADMIN_USERNAME = "school-admin"
$env:ADMIN_PASSWORD = "ضع-كلمة-مرور-محلية-قوية-هنا"
$env:SESSION_SECRET = (node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))")
npm ci
npm start
```

افتح `http://localhost:3000`. لا يبدأ الخادم في وضع الإنتاج ما لم تكن متغيرات الدخول الثلاثة مضبوطة. إذا شُغّل محليًا دونها، يبقى الموقع متاحًا للقراءة فقط ويكون تسجيل دخول الإدارة معطّلًا.

## الإعلانات والتخزين

تظهر لوحة الإعلانات في الصفحة الرئيسية، كما تتوفر في `/announcements.html`، وتقرأ من `/api/announcements` وتُحفظ في `data/announcements.json` (أو في المسار المحدد عبر `ANNOUNCEMENTS_FILE`). أما تعميمات المدرسة فتظهر في `/school-updates.html` فقط، وتُقرأ من `/api/updates` وتُحفظ منفصلة في `data/updates.json` (أو في المسار المحدد عبر `UPDATES_FILE`). يجب أن يشير متغيرا المسار إلى ملفين مختلفين. تبقى الإعلانات الموجودة حاليًا في ملف `announcements.json` إعلانات؛ ولا ينقل الخادم أي بيانات تلقائيًا. لكل عنصر تصنيف: عام، اختبارات، واجبات، فعاليات، أو تنبيهات. يستطيع الزوار البحث وتصفية النتائج حسب التصنيف. بعد تسجيل دخول الإدارة تظهر أزرار التعديل والحذف؛ وتتحقق واجهة API من صلاحية الإدارة لكل عملية، كما تتحقق من التصنيف والمحتوى قبل الحفظ. مجلد `data/` مستثنى من Git. استخدم استضافة ذات قرص دائم، أو عيّن متغيري `ANNOUNCEMENTS_FILE` و`UPDATES_FILE` إلى ملفات دائمة منفصلة، حتى لا تضيع البيانات عند إعادة تشغيل الخدمة أو إعادة نشرها. التخزين الحالي مناسب لخادم Node.js واحد؛ شغّل نسخة واحدة من الخادم لتفادي اختلاف الملفات بين النسخ.

لا تنشر الموقع على GitHub Pages أو أي استضافة ملفات ثابتة؛ تلك الاستضافات لا تشغّل واجهة API ولا تستطيع فرض صلاحيات النشر. عطّل GitHub Pages للمستودع إذا كان مفعّلًا سابقًا حتى لا تبقى نسخة قديمة منشورة. سير العمل في `.github/workflows/pages.yml` يشغّل الاختبارات فقط ولا ينشر الموقع. انشر تطبيق Node.js على استضافة تدعم تشغيل الخادم، واربط النطاق بـ HTTPS.
